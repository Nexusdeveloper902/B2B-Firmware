## Root-cause investigation (why the 401)

- Firmware path verified CORRECT against B2B-Core main: PAIRING mode
  POSTs `/api/v1/admin/cards/pair` with `Authorization: Bearer
  READER_API_KEY` (routes/api.php line 40; ResolveReaderToken does
  `Reader::where('api_key', $token)`).
- The 401 body is `{"status":"error","message":"Invalid bearer token"}`
  → no readers row matches the secrets.h key. The DemoSeeder generates
  its OWN random 32-char keys and prints them at `./run setup`; a
  user-invented secrets.h key is unknown to the backend.
- Separately, even a valid key would have returned `[409]`: pairing is
  arm-then-pair (admin must POST arm-pairing first; 45 s window;
  B2B-Core ADR-020). Nothing was armed.
- UX defect (the fixable one): the device printed no guidance on the
  mode switch and no remediation on the 401.
